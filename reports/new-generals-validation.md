# 新角色平衡與火痕效能驗證

日期：2026-10-08。遊戲基準：`0ddb807`。此次僅新增量測工具與報告，沒有更改角色數值、戰鬥規則、同步協定或特效。

## 結論與處置

- 保留目前角色數值。典韋在兩套策略都偏強、陸遜偏弱，但固定自動策略沒有真正的誘敵走位；結果不是玩家勝率，也不應據此直接削弱／加強。
- 優先考慮縮減火痕快照：將每片火痕重複攜帶的完整 owner 角色改為 P1／P2 編號，再由接收端還原。14片時 JSON 試算從14,326降至3,637 bytes（約75%）；本次未實作協定變更。
- 正常上限附近14片的桌面測試出現33.4ms的P95畫面間隔，屬值得追查的效能訊號；手機尺寸模擬沒有同樣的掉幀訊號。先用實機量測，再決定是否簡化每片火痕的裝飾特效。保留顏色、範圍、歸屬標記與淡出。
- 40片是超過目前雙陸遜正常上限的人工壓力測試，不能當作實際遊戲持續負載。

## 平衡測試

每個新角色對18位角色、30個固定seed、交換P1/P2，共3,240場；兩套策略共6,480場。使用遊戲同樣的1/120秒步長、雙方相同0.8發射品質、每0.5秒決策、seed交替先手。全部對戰終止，無非有限生命或座標。
策略A：專屬技優先，其餘通用技按seed輪替順序；策略B：只用專屬技。每個新角色排除鏡像後各1,020場。seed會影響策略順序，但部分角色與局面仍會重複，這不是6,480個獨立玩家樣本。未做勝率信賴區間推論。

## 繪製與畫面更新

本機 macOS Headless Chrome 154，--disable-gpu。桌面1440×1100、DPR1；手機模擬390×844、DPR2，沒有手機CPU降速，並非Safari或Android實機。每種情境先暖機10次，再取120次同步繪製樣本。特效隔離畫布780×500，計時含readback；整個戰場另計繪製及readback。
畫面間隔另以原生requestAnimationFrame測量，90幀略過暖機後79個間隔；每3幀做一次本機JSON快照套用。使用靜態人工火痕與雙方持續技能效果，並未包含完整遊戲模擬、聲音、真實網路及手機熱降速，所以不能換算成玩家實機FPS。

## 重跑

在遊戲根目錄先啟動 `python3 -m http.server 8082`，再依序執行（避免同時跑CPU工作干擾效能測量）：

```sh
node scripts/balance-benchmark.cjs
node scripts/balance-benchmark.cjs --signature-only
python3 scripts/fx-benchmark.py --fire
python3 scripts/fx-benchmark.py --fire --mobile
python3 scripts/remote-smoke.py --fire
node scripts/check.cjs
```

瀏覽器腳本使用macOS Google Chrome；遠端測試會短暫使用公開大廳房間1。原始量測在本目錄的五份JSON中。單次環境數據可作基線，後續優化應用相同環境重跑並多次比較。
